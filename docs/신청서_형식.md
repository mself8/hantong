# 신청서 형식과 대시보드 API

대시보드는 이 문서의 API만 쓰면 된다.

- 서버 주소: `https://hantong-production.up.railway.app`
- API를 직접 눌러 보기: `https://hantong-production.up.railway.app/docs`
- 로컬: `http://localhost:8000`

## 흐름

1. 어르신이 전화한다. 통화가 끝나면 Vapi가 통화 기록과 뽑은 항목을 서버로 보낸다.
2. 서버가 신청을 `processing`(정리 중)으로 저장한다. 몇 초 안에 병원·마을을 실제 목록에 맞추고 규칙으로 점검한다. 필요한 기관별 신청서를 만들어 `pending`(확인 대기)으로 바꾼다.
3. 공무원이 내용을 확인한다. 병원 후보가 여럿이면 하나 고르고, 신청서 칸을 고칠 수 있다.
4. 공무원이 '제출'을 누르면 `submitted`(기관 회신 대기)가 된다.
5. 기관 답을 신청서마다 확정이나 불가로 기록한다. 시연에서는 '기관 응답' 버튼으로 대신한다.
6. 모든 기관이 답하면 확정 안내문 초안이 자동으로 만들어지고 `confirmed`(안내 대기)가 된다.
7. 공무원이 안내문을 확인·수정하고 '발송'을 누르면 `notified`(안내 완료)가 된다. 시연에서는 발송 기록만 남긴다.

- 기관 신청이 필요 없는 건: 3번에서 안내문 초안이 바로 있다. 확인하고 발송하면 끝난다.
- 보류: 어느 단계에서든 `held`(보류)로 둘 수 있다.

## 기관별 신청서

| 종류(`type`) | 이름 | 만드는 조건 |
|---|---|---|
| `companion` | 병원동행 신청서 (홍천군노인복지관) | 같이 가 줄 사람이 필요하다고 했을 때 |
| `hope_taxi` | 희망택시 운행 요청서 (면사무소) | 사는 마을이 확인된 희망택시 운행 마을일 때 |
| `special_transport` | 특별교통수단 이용 신청서 (광역이동지원센터) | 휠체어가 필요하다고 했을 때 |

- 신청서 상태(`status`): `draft` 작성됨 → `submitted` 제출함 → `confirmed` 확정 / `rejected` 불가
- 가상 명부 20명 중 희망택시 운행 마을 주민은 없다. 희망택시 신청서를 보려면 통화에서 운행 마을(예: 서석면 생곡1리)을 말해야 한다.

## API

| 할 일 | 요청 |
|---|---|
| 목록 | `GET /api/requests` (상태로 거르기: `?status=pending`) |
| 상세 | `GET /api/requests/{id}` |
| 병원 고르기 | `POST /api/requests/{id}/hospital` 본문 `{"hosp_id": "HC040"}` → 아직 제출 안 한 신청서를 그 병원으로 다시 채운다 |
| 신청서 칸 고치기 | `PUT /api/requests/{id}/applications/{신청서 id}` 본문 `{"fields": {"진료 시각": "10:00"}}` (제출 전만) |
| 한꺼번에 제출 | `POST /api/requests/{id}/submit` |
| 하나만 제출 | `POST /api/requests/{id}/applications/{신청서 id}/submit` |
| 기관 응답 | `POST /api/requests/{id}/applications/{신청서 id}/respond` 본문 `{"result": "confirmed", "detail": "동행 매니저가 9시에 댁으로 찾아갑니다."}` (`result`는 `confirmed` / `rejected`) |
| 안내문 고치기 | `PUT /api/requests/{id}/message` 본문 `{"text": "…"}` (보내기 전만) |
| 안내문 발송 | `POST /api/requests/{id}/message/send` |
| 보류 | `POST /api/requests/{id}/hold` 본문 `{"memo": "날짜 다시 확인"}` |
| 상태 이름 | `GET /api/statuses` |
| 글로 시험 | `POST /api/requests` 본문 `{"text": "어르신: 담주 화요일 읍내 정형외과요"}` |
| 병원 목록 | `GET /api/hospitals?q=정형` |
| 마을 목록 | `GET /api/villages` (리별 65세 이상 인구와 비율 포함) |

- 순서에 맞지 않는 요청(이미 제출한 신청서를 또 제출 등)은 `409`와 이유(`detail`)를 돌려준다. 화면에 그대로 보여 주면 된다.
- 목록은 최근 신청이 먼저 온다. 새 신청을 보려면 5초마다 목록을 다시 불러오면 된다.
- 상태 이름: `processing` 정리 중, `pending` 확인 대기, `submitted` 기관 회신 대기, `confirmed` 안내 대기, `notified` 안내 완료, `held` 보류

## 신청 필드

- `id`, `created_at`(한국 시각), `status`, `source`(`phone` 전화 / `text` 글 시험)
- `call`: 통화 정보. `caller`는 가린 번호(`010-****-5678`), 웹 통화면 `null`. `recording_url`은 녹음 주소
- `resident`: 가상 명부에서 찾은 어르신. 못 찾으면 `null` → 화면에 '명부 확인 필요'
- `transcript`: 통화 기록. `role`은 `elder`(어르신) / `ai`
- `intent`: `hospital_visit` 병원 가는 날 / `medication` 복약 문의 / `cancel` 취소 / `companion` 동행 문의 / `other`
- `summary`: 한 줄 요약. 병원 방문은 서버가 바로잡은 날짜와 병원으로 만든다(예: `11월 24일(화) 11:00 · 읍내 정형외과 · 동행 필요`)
- `hospital`: `query`(어르신이 말한 표현), `department`, `status`(`matched` 한 곳 / `candidates` 여러 곳 / `unknown` 못 찾음), `candidates`(실제 기관 목록에서 고른 후보, 최대 5곳)
- `visit`: `date_expr`(말한 표현), `date`(YYYY-MM-DD), `date_source`(`rule` 규칙 계산 / `ai`), `time_expr`, `time`(HH:MM)
- `companion`: `needed`(`yes` / `no` / `unknown`), `reason`
- `wheelchair_needed`: `yes` / `no` / `unknown`
- `pickup`: `village`(맞춘 리), `village_code`, `detail`(통화에서 들은 상세 주소: 번지·가까운 건물), `point`(승차 지점: 상세 주소가 있으면 그것, 없으면 명부의 승차 지점)
- `evidence`: 항목별 근거가 된 어르신 말. 화면에서 각 항목 옆에 보여 준다
- `checks`: 규칙 점검 결과. `level`이 `warn`이면 빨간색, `info`면 회색으로 보여 준다
  - `hospital_unclear` 병원 미확정, `date_unclear` 날짜 미확정, `date_past` 지난 날짜, `holiday` 공휴일, `sunday` 일요일
  - `clinic_closed` 진료 안 하는 날·시간, `hours_unknown` 진료시간 정보 없음, `far` 홍천 밖 병원
  - `companion_deadline` 병원동행 7일 전 예약 마감, `village_mismatch` 명부와 다른 마을, `date_mismatch` 날짜 계산 엇갈림
  - `extract_failed` 자동 정리 실패 → 통화 기록을 보고 직접 처리
- `applications`: 기관별 신청서 목록
  - `id`(`A1`, `A2` …), `type`, `label`(신청서 이름), `agency`(보낼 기관), `contact`(기관 전화)
  - `status`, `fields`(신청서 칸 이름 → 값, 화면에 표로 보여 준다. `요금`·`상세 주소` 칸 포함), `notes`(공무원이 볼 주의 사항: 예약 마감, 사전 등록 필요, 관외 이용 제한 등)
  - `response`(기관 응답 `{result, detail}`), `history`
- `message`: 어르신께 보낼 안내문. 아직 없으면 `null`
  - `status`(`draft` 초안 / `sent` 보냄), `text`, `channel`(시연에서는 `기록`), `history`
- `memo`: 공무원 메모
- `history`: 신청 전체의 처리 기록 `[{at, status, note}]`

## 화면에서 꼭 보여 줄 것

- 목록: 상태, 받은 시각, 어르신(마을), 한 줄 요약, 경고 개수
- 상세 왼쪽: 항목마다 값과 근거 발화를 나란히, 경고, 통화 기록 전문, 녹음 듣기
- 상세 오른쪽: 기관별 신청서 카드(칸 표, 주의 사항, 상태)와 버튼
  - 병원 후보 고르기
  - 제출
  - 기관 응답(시연용, 확정·불가)
- 안내문: 초안 고치기와 발송 버튼, 보낸 뒤에는 보낸 시각
- 보류 버튼과 메모
